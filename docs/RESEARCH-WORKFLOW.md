## 用户选择的更新模式

使用已有抽取结果，新增资料审核后批量更新。PDF不在浏览器中假装OCR、向量化或LLM评分。新增资料批次清单只登记文件名、大小、SHA-256、资料类型、地区、用途、可信度和待审状态；需与原文件一起交给批次操作人员。

1. 检查资料来源、重复文件、适用范围。
2. 在原RAG工作台执行解析、切分、抽取；保留页码、文档ID与片段ID。
3. 核验新成果。候选关系不等同确定事实；候选指标需补齐定义、单位、方向、适用范围、评分锚点、方法与审核依据。
4. 更新输出路径后运行 `python3 scripts/import-rag-workbench.py`，检查所有来源哈希一致；禁止用未匹配版本覆盖。
5. 构建并发布公开快照。原始27项正式指标和已有文物评分不因候选草案自动改变。

## 参考原型与实际能力

所提供 index.html 仅作为流程粒度参考。线上不再嵌入其独立界面；规则配置、PDF 检索、指标证据链和专家复核均使用平台原生界面。原型的默认补分、启发式置信度与示例 LLM 输出不进入真实计算结果。
新增独立调试台使用真实文物字段，人工配置规则；缺失/不命中为null。文献召回采用关键词匹配，无向量相似度、无LLM置信度。模型接口未配置，后续可接入但须保留审核与版本机制。

本机标准草案仅保存在当前浏览器，导出后交管理员审核。云端服务与公开静态快照能力不同；当前Sites连接返回项目不存在，因此本次仅能部署GitHub Pages，未宣称云端数据库更新。


## 原生资料图谱与 PDF 指标证据链（2026-11-06）

- 数据管理以 RAG_datasource 为资料库，移除旧“规则与评价流程参考”页签及原型 HTML 发布副本。全图由平台原生组件呈现，继承 HERISK 深浅色主题、字号与控件；支持实体/类型/PDF 筛选、邻域、关系原文、键盘列表、缩放和导出。8,833 个实体及 5,083 条关系完整保留。默认勾选“仅显示关联网络（≥3 实体）”显示 2,285 个实体、1,802 条关系，其余 6,548 个两两孤立实体可取消勾选查看，避免整图被孤立点淹没。
- 图谱到候选标准先匹配实体名；无直接命中时明确展示同源文献候选，不能将同源关系误写为已批准标准。
- `prepare-rag-evidence.py` 逐一核对 41 份 PDF 的 SHA-256，用与哈希绑定的页文本检查引文。5,138 条抽取记录均通过空白/Unicode 归一化后的字面比对，合并成 4,834 条唯一摘录，实际引用覆盖 34 份 PDF。字面校验不等于语义审核；OCR 错字及现行效力仍需核对原文件。
- 每个建筑的每项指标通过建筑 ID 和指标 ID 组织：相关字段、检索问题、引用 PDF/页码/原文、条件与缺口、原评分依据、专家复核。资料库和证据链不再把“历史价值”Excel 文件当成专业知识来源。原始评分数据及完整来源仍保留在导出的证据链中，不改写为 PDF 生成结果。
- 检索为显式的指标关键词、语境过滤、材料关键词和文献多样性排序；无向量相似度、LLM 新评分或虚构置信度。当某指标在文献库中没有直接对应条文（如“历史事件/人物关联”“城市地标性”）时，回退到同维度语境词并**明确标注**“同维度相关依据、非对象专属、不用于自动评分”；显式检索词不会触发回退，指定关键词无命中时仍显示为空缺口。
- 引用卡片可查看对应 PDF 物理页的解析文字，显示文件名、文件哈希、页码、claim 与 chunk 标识，并加入专家意见；仅操作引用不保存评分。超过复核字数限制时拒绝添加并提示导出。
- 本机标准草案与专家复核不自动覆盖正式标准；已提供的 PDF 抽取结果没有经审核的 1—5 分规则映射，界面明确提示待审核。
